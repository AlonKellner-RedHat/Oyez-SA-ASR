## Types of cases not yet normalized

### 1. No normalization rule (full gap)

- **Mixed case (e.g. McFarland, MacFarland, McKamy)**  
  - 782 distinct spans, 9,150 occurrences.  
  - No Phase 3 rule; names and CamelCase words are left as-is.

- **Long all-caps (6+ letters, e.g. UNIVAC, CUSTOM, NAVMED)**  
  - 166 distinct spans, 1,653 occurrences.  
  - Rule 15 covers *known* acronyms only; unknown long all-caps have no rule.

- **Digit+letter mixed (e.g. 37th, 3rd, 80th, H1N1)**  
  - 1,384 distinct spans, 13,737 occurrences.  
  - Mix of ordinals (3rd, 37th), alphanumeric IDs, and product names. No single rule; ordinals and case IDs have separate rules but not this mixed pattern as a class.

- **Brackets (curly)**  
  - 2 candidates (e.g. `{Voice overlap}`, `{b}`), 2 occurrences.  
  - No rule for curly-bracket content.

- **Brackets (numbered list, e.g. 1), 2), 8))**  
  - 74 candidates, 23,243 occurrences.  
  - Plan mentions structural list markers; no explicit normalization in current scripts.

### 2. Optional or partial normalization

- **Non-ASCII (e.g. curly quotes “ ”, accented words)**  
  - 19,614 candidates, 140,926 occurrences.  
  - **Rule 25** (Quote marks / Unicode) is **optional**: straight quote; dash → hyphen or "to"; ellipsis omit. Not applied by default.

- **Other char (same typographic/quote tokens as non_ascii)**  
  - 19,497 candidates, 140,444 occurrences.  
  - Largely overlaps non_ascii (curly quotes, symbols). No default normalization.

- **Symbols (e.g. –, –-, -–, ellipsis)**  
  - 1,124 candidates, 7,692 occurrences.  
  - **Rule 25** (em dash, ellipsis) is **optional**; not applied by default.

- **Brackets (parentheses)**  
  - 353 candidates, 141,461 occurrences.  
  - **Rule 27**: non-speech content (e.g. (Inaudible), (Laughter)) is stripped. Structural (a), (b), (1), (2) may be normalized to spoken; other parenthetical content has no rule.

- **Brackets (square)**  
  - 306 candidates, 16,252 occurrences.  
  - **Rule 27**: non-speech (e.g. [Laughter], [cough]) strip. **Rule 28**: editorial [= X] replace with normalized X. Other square-bracket content not normalized.

### 3. Planned but not in build_rule_candidates

- **Leading decimal (e.g. .000015, .99, .10)**  
  - 32 candidates, 73 occurrences.  
  - **Rule 26** specifies: ".N (not year)" → "point" + digits. This is in the plan and in `rule_normalizations` (leading_decimal not exposed there), but **not** in `build_rule_candidates.py`, so these spans are awareness-only in the pipeline.

## Recommendations

1. **Leading decimal:** Add Rule 26 to `build_rule_candidates` (or a dedicated step) so leading decimals are normalized to "point" + digits.
2. **Non-speech and editorial brackets:** Implement Rules 27 and 28 so (Inaudible), [Laughter], [cough], and [= X] are stripped or replaced.
3. **Optional Rule 25:** If desired, enable Quote marks / Unicode normalization so curly quotes, em dash, and ellipsis are normalized.
4. **Mixed case and long all-caps:** Keep as awareness-only unless product/name rules are added; no plan rule today.
5. **Digit+letter mixed:** Handle via existing ordinal and case-ID rules where applicable; rest remain awareness-only.
6. **Numbered and curly brackets:** Either add structural/display rules or leave as awareness-only.
